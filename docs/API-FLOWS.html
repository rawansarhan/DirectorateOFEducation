1. الأدوار (Actors)

الدورالمسؤولية
المسؤول التقنييرفع BPMN، يضبط مراحل الاستمارات، يراجع ويوافق على العملية
المواطن / الموظف (مقدّم الطلب)يختار نوع المعاملة، يملأ الاستمارة، يقدّم الطلب
الموظف (معالج)يستلم المهام، يقفل المعاملة، يوقّع USB، يوافق أو يرفض

2. الجزء الأول — إعداد العملية (Admin)

الهدف: تحويل ملف BPMN إلى عملية جاهزة للاستخدام من المواطن والموظفين.

2.1 سيكوانس إنشاء وتفعيل العملية

[1] المسؤول التقني → Frontend Admin
[2] POST /api/process_definitions/create  (multipart: BPMN + name + priority + type_trans_id)
    → Deploy Camunda → حفظ process_definitions + stages
[3] POST /api/stage_config/create  ({ stages: [{ stage_id, config_json, assignments }] })
    → حفظ stage_configs + stage_assignments
[4] GET /api/process_definitions/{id}/details
    → { process, stages, validation: { is_valid, errors } }
[5] إذا is_valid = true:
    POST /api/process_definitions/{id}/review  { decision: "APPROVE" | "REJECT" }
    → approval_status = APPROVED → العملية جاهزة للجمهور

2.2 شرح خطوة بخطoة (للفرونت)

#APIمتىملاحظات
1POST /api/process_definitions/createإنشاء عمليةmultipart: file BPMN + name, priority, type_trans_id — صلاحية PROCESS_CREATE
2POST /api/stage_config/createإعداد المراحلstages[]: stage_id, config_json, assignments[] — STAGE_CONFIG_CREATE
3GET /api/process_definitions/{id}/detailsمعاينة/تحققاعرض validation.errors — لا تفعّل الموافقة إذا is_valid=false — PROCESS_VIEW
4POST /api/process_definitions/{id}/reviewموافقة/رفض{ decision: "APPROVE" | "REJECT" } — PROCESS_APPROVE

ماذا يحدث للـ Stakeholders؟

  1. رفع BPMN — النشر في Camunda + حفظ المراحل.
  2. إعداد المراحل — استمارة + تعيين الدوائر/الأدوار.
  3. التحقق — التأكد من اكتمال الإعدادات.
  4. الموافقة — بعدها فقط تظهر للمواطن/الموظف.

3. الجزء الثاني — تقديم المعاملة

الهدف: من اختيار النوع حتى إرسال الطلب وبدء سير العمل.

3.1 سيكوانس رحلة مقدّم الطلب

[1] GET /api/typeProcess                          → أنواع المعاملات
[2] GET /api/process_definitions/auth/{typeTransId} → عمليات AUTH المعتمدة
[3] المستخدم يختار processId
[4] بالتوازي:
    GET /api/transaction/draft/{processId}         → مسودة إن وُجدت
    GET /api/stage_config/config/{processId}       → config_json (widgets)
[5] عرض الاستمارة
[6] (اختياري) POST /api/transaction/upsertDraft/{processId}  → حفظ مسودة
[7] POST /api/transaction/{transactionId}/submit → إرسال + بدء workflow (outbox)
    → بدون توقيع USB — idempotency_key يولّده السيرفر

3.2 جدول APIs — Portal

4. الجزء الثالث — معالجة المهام (موظف)

4.1 سيكوانس معالجة مهمة

[1] GET /api/workflow/tasks              (بانتظار + قيد التنفيذ)
    أو GET /api/workflow/tasks/in-progress
    أو GET /api/workflow/tasks/pending-pickup
[2] المستخدم يختار taskId
[3] GET /api/workflow/tasks/{taskId}     → قفل (task lock) + config
[4] إذا requires_digital_signature:
    POST /api/workflow/tasks/{taskId}/signing-challenge  { pin, decision }
    → توقيع message عبر USB
    POST /api/workflow/tasks/{taskId}/complete  { signature, idempotency_key, ... }
[5] النتيجة: approve → مرحلة تالية | reject → إغلاق + status=rejected

4.2 قوائم المهام

APIالاستخدام
GET /api/workflow/tasks?status=activeبانتظار الاستلام + قيد التنفيذ
GET /api/workflow/tasks/in-progressقيد التنفيذ فقط (مقفولة لدي)
GET /api/workflow/tasks/pending-pickupبانتظار الاستلام فقط
GET /api/workflow/tasks?status=completedمنجزة
GET /api/workflow/tasks?status=rejectedمرفوضة

حالات العنصر

6. ملخص Stakeholders

مرحلة الإعداد

BPMN → إعداد الاستمارات والدوائر → تحقق → موافقة → جاهزة للجمهور

مرحلة التقديم

اختيار النوع → اختيار العملية → ملء استمارة → (حفظ?) → إرسال → workflow يبدأ

مرحلة المعالجة

قائمة مهام → فتح (قفل) → توقيع USB → موافقة/رفض → مرحلة تالية أو إغلاق

مسار التقديمsubmitنفس APIs إن قدّم لنفسه

7. خريطة الشاشات → APIs (Cheat Sheet)

[Admin]
  إنشاء عملية    → POST /api/process_definitions/create
  إعداد مراحل    → POST /api/stage_config/create
  معاينة         → GET  /api/process_definitions/{id}/details
  موافقة/رفض     → POST /api/process_definitions/{id}/review

[Portal]
  أنواع          → GET  /api/typeProcess
  عمليات         → GET  /api/process_definitions/auth/{typeId}
  استمارة        → GET  /draft/{processId} + GET /stage_config/config/{processId}
  حفظ            → POST /api/transaction/upsertDraft/{processId}
  إرسال          → POST /api/transaction/{id}/submit

[Employee]
  مهامي          → GET  /api/workflow/tasks
  تفاصيل+قفل     → GET  /api/workflow/tasks/{taskId}
  تحدي توقيع     → POST /api/workflow/tasks/{taskId}/signing-challenge
  إكمال          → POST /api/workflow/tasks/{taskId}/complete
